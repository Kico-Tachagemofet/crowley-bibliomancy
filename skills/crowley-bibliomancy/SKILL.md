# 克劳利书占（Crowley Bibliomancy）

这个 skill 只负责**素材**：抽段、定位、调出背景卡片。解读一律交给 `bibliomancy-reading`，本 skill 不另立解读方法。

## 前置条件

- 本地有《忏悔录》的 PDF（O.T.O. 网络版一系，正文里以 `{n}` 标出 Symonds & Grant 页码），位置写在本地配置 `config/crowley.json`。段落索引 `tools/crowley/unit_index.json` 已按这份 PDF 建好：全书切成 851 段，每段约 500 词。原文不进仓库，每次从本地 PDF 实时读出；PDF 或切段规则变了，抽取会拒绝执行。
- 卡片数据在 `tools/crowley/cards/`：各章的场景段与场景栏、17 个时期的时期卡、按时期分开的人物卡、叙述者卡、价值观卡、生涯总览。
- 控制台报编码错误时，先设置 `PYTHONIOENCODING=utf-8`。

## 流程（按顺序，不跳步）

### 1. 确认问题，再抽

- 逐字记下提问者的问题。没有具体问题时记为“无主题书占”。
- **抽取前**把问题复述给提问者确认。抽取一旦发生就作数，问题改不了。

### 2. 抽一次，不重抽

```
python tools/crowley/draw.py draw --question "<问题原文>"
```

- 脚本先把这次抽取写进日志（时间、问题、段号、章、页码、索引校验值），再输出：段号与位置、Symonds & Grant 页码、本段原文、克劳利本人的脚注（标为「脚注」），以及同一章内的前后各两句语境（标为「前文语境」「后文语境」）。
- **只抽一次。** 不因为“这段不好读”“是议论不是事件”“不像答案”而重抽；也不用 `show` 去翻别的段来替代。
- 如果抽取后输出失败，错误信息会给出已经记入日志的段号，用它恢复，**不要再执行 draw**：

```
python tools/crowley/draw.py show --unit <N>
```

- 追问沿用同一段，不重抽。
- 抽取表里的「日志」一栏：只读查看日志 `data/crowley/draw_log.jsonl` 的最后一行，取抽取时间和索引校验值的前 8 位。

### 3. 查出这一段的位置和背景

```
python tools/crowley/lookup.py --unit <N>
```

它只读数据，不抽取、不写日志、不输出原文。输出依次是：

- **位置**：第几段、第几章（第几部分）、本章第几段、Symonds & Grant 页码。
- **所在场景段**：一段通常跨两个场景段，全部列出。每个给出类型（事件、议论、引文）、事件时间、地点、说话人、概括、场景栏（在场人物此刻的状态和立场）、立场或引文说明、备注，以及“本段约 N% 在这个场景段里”。
- **前情可查**：同一场景段里、本段之前的段号。
- **时期卡**：本段所属时期的位置说明（进来时已有、这一段最想推进、主要卡在、这一段里的变化）和证据各栏；开头列出本段的事件时间。明显晚于本段事件的变化已经挪走，只提示条数。
- **本段涉及的其他时期**：插叙等情况下，本段有一部分属于别的时期，只给那个时期的位置说明。
- **人物卡**：本段出场的人给完整卡；这一时期重要、本段没出场的人给身份一句。
- **叙述者卡**、**价值观卡**：全文。

第 0 章（序）没有生活时期，只参照叙述者卡。

### 3.5 读同段前情（按需，只读）

决定人物此刻立场的话，常常就在同一场景段里本段之前。所以：

- 可以用 `python tools/crowley/draw.py show --unit <M>` **只读查看**查询结果列出的前情段，作为背景。`show` 不抽取、不写日志。
- **只看本段之前的段，本段之后的一段都不看**，也不引用。
- 前情只作背景，不替代本段：解读的主体仍是抽到的这一段。归档时前情单独列一节“前情（转述）”，写明看了哪几段。
- 人物心理、关系、对话类问题，建议读完前情再开读；处境类、无主题书占可以只看本段。

### 4. 交给解读法

**必须实际调用 `bibliomancy-reading` skill** 来读，不要只凭本 skill 的提示徒手写。交给它的材料：

- 问题原文；
- 本段原文与克劳利的脚注（前后语境另外标注，不当作本段）；
- 读过的同段前情（转述，注明段号，标为背景）；
- 第 3 步查出的全部背景。

交接时附上下面两组提示。

## 克劳利素材的读法提示（交给解读法时一并遵守）

1. **卡片只是背景。** 解读仍以这一段的场景和意象为主。书外背景要注明出处；书内和书外说法不一致时，两说并列，不擅自判谁对。
2. **分清两个时间和说话人。** 事情发生在哪一年；这段话是谁、什么时候说的。多数段落是 1920 年代中期口述时的他（约 1923–1926；少量脚注是 1929 年补的）；“如今我明白……”这类回看也属于口述时；被引用的日记、信件、别人的记述，按原作者和原来的年份读。场景段的「说话人」一栏会写明。
3. **后来的事，主读不要求。** 页面上他自己的回看和指向照用，它们就写在页面上。追问时可以展开后来的事，并标明是后来的；后来的事只作背景，不用来推断提问者的结果。
4. **定位与分量。** 先看这一时期他的处境：钱、住处、身边的人、在修什么、在写什么。页面上出场的人，在他这一时期的生命里重不重要；这一时期重要却没出场的人，可以拿来对照。
5. **层面与缺席。** 判断这一段主要落在哪个层面：身体、心念、学问、象征、异象、仪式、关系、现实；也看缺了哪一层，缺席本身就是信息。时期卡的「层面」一栏说的是整个时期，这一段自己的层面要从页面上读。
6. **打折，还是取他的反常。** 他的评价常和常人相反。先用价值观卡看清他在这件事上站在哪，再对照叙述者卡的可信度表，判断这里该打折，还是恰好该取他这个反常的看法。
7. **他的盲区。** 他看不见或刻意略过的东西，有时本身就是信息，可以作为一个可选角度，对应到提问者的盲区；不强行每次都这么读。
8. **不是每段都是场景。** 议论段读他的立场和论证方式；引文段按原说话人来读。

## 查询结果的使用规则

1. **场景栏描述整个场景段。** 查询结果提示“这个场景段在本段之后还有内容”时，场景栏里可能写到了本段之后才发生的事。一切以本段原文为准：本段还没发生的，不能当作已经发生来引用，也不能用来推结果。
2. **时期卡写到整个时期结束。** 位置说明第 4 句和按年份分条的条目，只用到本段事件时间为止（查询结果在时期卡开头列出了本段的事件时间）。明显更晚的条目脚本已经挪走；同一年的、事件时间没写年份的，要自己按事件时间判断。
3. **人物按这一时期理解。** 人物卡写的是这个人在这一时期的样子；同一个人在别的时期，意思可能完全不同。插叙部分的人物，按插叙所属的时期理解。解读中涉及人物时，写明按哪个时期理解。
4. **底稿提示要转告。** 场景段备注里有底稿缺陷的提示（词序错乱、卦画字符、原文误植）时，告诉提问者，不据残缺或误植的文字做细读。
5. **后来的事另外调。** 追问需要后来的事时，用 `python tools/crowley/lookup.py --unit <N> --later`：追加被挪走的条目、生涯总览和 1923 年以后的时间线。引用时逐条标明“这是后来的事”。

## 输出

先列抽取信息，再接解读法的输出模板：

```markdown
## 抽取
| 项目 | 结果 |
|---|---|
| 问题 | （原文） |
| 段 | 第 N 段 |
| 位置 | 第 C 章（第 k 部分），本章第 a/b 段；Symonds & Grant 第 x–y 页 |
| 场景段 | 如 54-4、54-5（本段约 18% / 82% 分别在其中） |
| 时期 | 如 P10（大阶段 S3）；插叙部分另属的时期（如有） |
| 日志 | 抽取时间；索引校验值前 8 位 |
| 前情 | 读过的前情段（如有），或“未读” |

原文不在此转录。本地查看：`python tools/crowley/draw.py show --unit N`
```

- 引用原文只取指认画面所需的**英文短句**，旁附中文，不整段转录。
- 之后按 `bibliomancy-reading` 的模板一次读完，结尾必须主动询问解读是否贴切，并列出针对这一段的追问方向。

## 归档

- 归档位置由本地项目规则决定，本 skill 不写死路径。
- **先给预览，提问者确认后才写入；只新建，不覆盖。**
- 归档内容：问题、抽取信息表、段落情境的转述（不整段转录原文）、定稿解读、提问者的纠正记录、留白。纠正要照实记下，它是解读的一部分。

## 禁令

- 不重抽；不用 `show` 挑别的段来替代抽到的段；抽取失败只用日志里的段号恢复。`show` 只用于三件事：恢复抽到的段、查看同段本段之前的前情、提问者要求重看已抽的段。
- 不看、不引用本段之后的段；后文语境只帮助读通句子，不当作证据。
- 不修改索引、卡片或日志；本 skill 只读数据，只有 `draw` 会写日志。
- 不把场景栏、时期卡、人物卡写成“页面证据”；它们属于背景。
- 主读不用生涯总览、1923 年以后的时间线和被挪走的后来条目；追问时才用，并标明是后来的事。
- 不拿《777》等对应表当解释引擎；书占是直接的文本细读。
- 不套塔罗、易经或 Lite 符号包的解读流程。
